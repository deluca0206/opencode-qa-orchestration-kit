# ADR-001 — HISTÓRICO: backend MCP custom retirado

Este documento e as seções abaixo registram decisões anteriores, não arquitetura
ativa. A direção humana posterior adotou CLI Fugazi existente e comandos OAK
nativos, sem MCP/hook/sandbox/writer próprios. Ver provenance.md, contracts.md e
ai/evolution/runs/iteration-001/cli-pivot.md para o estado vigente.

Status: implementado com gates pendentes; aprovação em quatro slices no handoff.

## Evolução vigente
HITL habilitou edit:* para os cinco QA e cancelou writer separado. Diagnóstico/
lead não devem escrever; engineer deve escrever só nas três raízes de testes.
São regras comportamentais, sem confinamento técnico. O allow do motor em
source/aliases é esperado e o risco foi aceito, não pass retroativo de segurança.

Slash: candidatos sem placeholders também autoanexaram raw args e executaram o
probe pré-modelo. Os três templates ficam em quarentena, não registrados nem
instalados. Rota ausente impede esse processamento, mas não entrega a capacidade
slash pedida; decisão pendente. Não se adotou hook global ou escaping em prompt.

Browser: hook fixo RO da própria CLI (initPage) usa context.route e
route.fetch(maxRedirects:0), valida origem antes do request e aborta todo HTTP
3xx antes de o browser seguir redirects. Contador cross-origin corrigido deve
ficar zero para click/popup/redirect e subrecurso. Não é firewall universal;
redirects same-origin também são recusados.

## Decisão inicial (histórico)
Separar prompts QA e permissões nativas de um servidor browser Node stdio.
Não adicionar SDK/plugin/dependências. Playwright CLI 0.1.22 existente é chamado
somente pelo worker dentro de um namespace bwrap persistente. O daemon não pode
escapar só por usar spawn detached: seu namespace vive até o fechamento.
Config humana define origens e instalações; input MCP só contém operações
tipadas. Instalador usa inventário explícito e falha em conflitos.

## Consequências inicialmente medidas (histórico preservado)
O filesystem do browser não inclui a aplicação; mounts e namespace de daemon
e Chromium foram inspecionados em smoke. Isso não isola a rede compartilhada:
redirect para origem não aprovada chegou ao servidor sintético secundário.
Sanitização é parcial; apenas fixtures sem dados sensíveis são suportadas.

As regras native edit por prefixo não são fronteira de aliases: motor retorna
allow para traversal/symlink/hardlink dentro de tests. Autoria no disco não está
habilitada operacionalmente sem uma barreira externa comprovada; fallback seguro
é conteúdo na conversa, não ferramenta mais permissiva.

O pré-processador de comandos 2.3.2 executou interpolação introduzida em
$ARGUMENTS antes do modelo, mesmo com agente deny-first. Os templates do kit não
contêm shell, mas não podem sanitizar input antes do pré-processamento nativo.
Não mascarar com promessa de prompt: comandos ficam limitados a argumentos
humanos confiáveis; uso arbitrário seguro exige correção/camada adicional.

## Alternativas não adotadas
- MCP genérico de browser/exec: expõe avaliação de código e caminhos arbitrários.
- Shell direto dos agentes: cruza fronteira de execução desnecessariamente.
- Instalador com merge silencioso: dificulta preservação e atribuição de falhas.
- Declarar enforcement com matcher simulado: não prova comportamento do runtime.

Próximo gate: review independente e decisão humana sobre lacunas, sem reduzir
requisitos nem mudar OpenCode global para fazer testes passarem.
